# 同名カードの重複建設制限の実装計画

## 現状の課題
- シミュレーターにおいて、同じ名前（同じID）のカードを複数枚建設できてしまう。
- ユーザーの指摘により、これは意図しない挙動（またはルールの不備）であると判断される。

## 修正方針
1. **建設可否判定の強化**:
   - 単なるコストチェックだけでなく、既に建設済みのカード（Tableau）に同名のカードが存在しないかをチェックするロジックを追加する。
2. **UIの反映**:
   - 建設ボタンが有効になる条件に上記チェックを含める。
   - ボタンが非活性な理由（リソース不足なのか、既に建設済みなのか）をツールチップ等でユーザーに伝える。
3. **AIの制御**:
   - AIが重複したカードを建設しようとしないようにロジックを修正する。

## 実装内容
- `Game` クラスに `canBuild(player, card)` メソッドを実装する。
  - 資源が足りているか（既存の `checkCost` を呼び出す）。
  - `player.construction` に `card.id` と同じ ID のカードが含まれていないかを確認する。
- `showExecutionActions` (人間用) と `executeAITurn` (AI用) の判定ロジックを `canBuild` に置き換える。
- `showExecutionActions` でボタンを非活性にする際の `title` (ツールチップ) を動的に変更する。

## 期待される効果
- 同じ建物が複数並ぶことがなくなり、多様な建物を建てる戦略性が向上する。
- ユーザーの期待する「重複建設不可」のルールが正しく適用される。
