# 相乗りルールの修正実装計画

## 現状の課題
- シミュレーターの「相乗り（ride-sharing）」ルールが、同じマスにいる全プレイヤーを運ぶ実装になっている。
- 本来のルール（`rule.md`より）では、「自分の上に他人のコマがあれば、全員乗せたまま運ぶ」となっており、スタック（積み重ね）構造が必要。
- 現在の実装では、駒が磁石のように全員一緒に動いてしまい、戦略性が失われている。

## 修正方針
1. **スタック構造の導入**: 各マス（Node）ごとに、どのプレイヤーがどの順番で重なっているかを管理する `nodeStacks` を `Game` クラスに追加する。
2. **移動ロジックの変更**:
   - 移動するプレイヤーよりも「上」にいるプレイヤーのみを「乗せている（passengers）」と判定するように変更。
   - 移動後、移動したプレイヤーとその同行者は、目的地の既存のスタックの「一番上」に追加される（相対的な順序は維持）。
3. **視覚的なフィードバック**:
   - マップ上の駒の表示位置を、スタックの順序に基づいてオフセットさせ、重なり順がわかるようにする。

## 実装ステップ

### 1. Gameクラスの初期化 (`simulator/game.js`)
- `nodeStacks` オブジェクトを初期化。
- ゲーム開始時、全プレイヤーを Node 1 のスタックに（とりあえずID順で）追加。

### 2. 相乗り判定ロジックの修正
- `getPassengers(player)` メソッドを新設し、スタック内で指定プレイヤーよりインデックスが大きいプレイヤーを抽出する。
- `executeMove` (人間用) と `executeAITurn` (AI用) でこのロジックを使用するように更新。

### 3. スタックの更新処理
- 移動完了時に `nodeStacks` を更新する `updateNodeStacks(player, targetId, passengers)` メソッドを実装。
- 元のマスから移動グループを削除し、新しいマスのスタックの末尾（上）に追加。

### 4. UI描画の更新
- `renderMap` メソッドで、`nodeStacks` のインデックスを使用して `left` / `top` のオフセットを計算する。

## 期待される効果
- ルールブック通りの「自分より上にいる人だけを運ぶ」挙動が再現される。
- 下にいるプレイヤーが動くことで上のプレイヤーを運ぶ恩恵が得られる一方、上にいるプレイヤーは自由に（下のプレイヤーを置いて）動けるようになる。
